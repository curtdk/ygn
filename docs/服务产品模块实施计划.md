# 上门服务模块实施计划

## 项目背景

基于现有美杜莎商城系统，新增独立的上门服务产品体系：
- 原有实物商城所有功能完全保留
- 新增服务产品独立体系，互不干扰
- 共用同一套用户账号体系

---

## 阶段一：数据模型与用户身份系统

### 1.1 数据库设计

**新增数据表：**

| 表名 | 说明 |
|------|------|
| `service_provider` | 服务人员信息表（**扩展现有用户，非新建用户**） |
| `service_provider_application` | 服务人员入驻申请表 |
| `service_product` | 服务产品扩展表 |
| `service_order` | 服务订单表 |
| `service_order_grab` | 抢单记录表 |
| `service_commission` | 佣金记录表 |
| `service_profit_share` | 分润记录表 |
| `profit_share_log` | 分润台账表 |
| `customer_referral` | 用户推荐关系表 |

**修改现有表：**
- `product` - 新增 `product_type` 字段（product/service）
- `customer` - 新增 `referrer_id` 字段（推荐人ID）、`referral_code` 字段（推荐码）

### 1.2 用户推荐关系模型（分润基础）

**数据结构：**
```
customer (用户表)
├── id                      # 用户ID
├── referrer_id            # 推荐人ID（上级）
├── referral_code          # 用户的推荐码
└── ...其他字段

customer_referral (推荐关系表)
├── id
├── customer_id            # 用户ID
├── level                  # 推荐层级 (1/2/3)
├── referrer_id            # 上级推荐人ID
└── created_at
```

**分润链路逻辑：**
- 用户A推荐用户B → B为一层级推荐人
- 用户B推荐用户C → C为A的二级推荐人（同时是B的一层级）
- 用户C推荐用户D → D为A的三级推荐人

**推荐码生成规则：**
- 自动生成唯一推荐码（8位字母数字组合）
- 用户可通过分享推荐码邀请新用户

### 1.3 服务人员身份系统

**说明：** `service_provider` 表是**扩展现有用户**的信息表，非新建用户。

**前端功能：**
- 个人中心新增"申请成为服务人员"入口
- 申请表单：手机号、身份证正反面、工作证件、荣誉证书上传
- 申请状态查询页面

**后台功能：**
- 资质审核列表（待审核/已通过/已拒绝）
- 审核操作：通过/拒绝/查看详情
- 服务人员管理列表

### 1.4 交付物
- 数据库 Migration 文件
- 后端 Module: `service-provider`
- 前端：申请表单、个人中心入口
- 后台：资质审核页面

### 1.5 测试要点
- [ ] 用户成功提交入驻申请
- [ ] 后台可查看并审核申请
- [ ] 审核通过后用户解锁服务人员权限

## 阶段三：服务订单流程

### 3.1 订单创建与支付

**复用现有服务购买流程：**
- 用户选购服务产品 → 结算页面 → 支付
- 订单创建时标记为服务订单类型

**新增功能：**
- 订单创建后自动记录服务订单信息
- 订单关联服务人员和客户信息

### 3.2 订单审核

**后台配置：**
- 全局开关：订单审核模式（自动审核/人工审核）

**自动审核模式：**
- 支付成功后自动审核通过
- 进入抢单池

**人工审核模式：**
- 后台订单列表新增"审核"操作
- 审核通过后进入抢单池

### 3.3 抢单池

**后台功能：**
- 抢单订单列表（待抢单订单）
- 显示订单基本信息（服务类型、地点、时间要求）

**前端功能（服务人员专属）：**
- 抢单列表页面 `/service/grab`
- 显示可抢订单
- 一键抢单操作

**业务逻辑：**
- 仅已认证服务人员可见
- 订单被抢后锁定，其他服务人员不可再抢

### 3.4 派单系统

**后台配置：**
- 全局开关：派单模式（自动派单/人工派单）

**自动派单：**
- 抢单成功后直接生效
- 服务人员接单

**人工派单：**
- 后台支持平台指派服务人员
- 可从服务人员列表选择

### 3.5 服务执行

**前端功能（服务人员）：**
- 我的服务订单列表 `/service/my-orders`
- 订单状态：已接单 → 服务中 → 已完成

**开启服务：**
- 服务人员上传现场合照凭证
- 点击"开启服务"按钮
- 订单状态更新为服务中

**结束服务：**
- 服务人员点击"结束服务"
- 手动提交完成

### 3.6 订单完结与评价

**自动完结：**
- 后台配置：订单自动完结时长（如：48小时）
- 用户未手动确认，超时自动完结

**用户评价：**
- 订单完结后弹出评价窗口
- 1-5星评分
- 评价内容（复用现有评价功能）

### 3.7 交付物
- 后端 API：订单审核、抢单、派单
- 前端：抢单页面、服务人员订单管理
- 后台：订单管理、配置面板

### 3.8 测试要点
- [ ] 服务人员可正常抢单
- [ ] 后台可人工派单
- [ ] 服务人员可上传凭证、开启/结束服务
- [ ] 订单自动完结机制正常

## 阶段四：佣金与分润系统

### 4.1 佣金结算

**后台配置：**
- 全局开关：佣金结算模式（自动结算/审核结算）

**自动结算：**
- 订单完成后自动计算并发放佣金
- 佣金 = 订单金额 × 佣金比例

**审核结算：**
- 后台显示待结算佣金列表
- 人工审核后发放

**后台功能：**
- 佣金结算列表
- 执行结算操作
- 佣金流水查询

### 4.2 三级分润

**分润逻辑：**
- 下单用户推荐链分润（三级）
- 服务人员推荐链分润（三级）
- 各层级独立开关控制

**分润计算流程：**
```
订单完成
    ↓
计算佣金（服务人员获得）
    ↓
计算分润（基于推荐链）
    ├── 一级推荐人：A推荐B下单 → A获得分润
    ├── 二级推荐人：B推荐C下单 → A获得分润
    └── 三级推荐人：C推荐D下单 → A获得分润
    ↓
记录分润台账
```

**后台功能：**
- 分润配置面板（显示/隐藏各层级开关）
- 手动执行分润按钮
- 分润记录查看

### 4.3 分润台账

**数据库：**
- `profit_share_log` 存储所有分润明细
- 字段：订单编号、用户、分润金额、收支类型、来源用户、推荐链关系

**前端功能：**
- 个人中心新增"分润记录"页面
- 服务人员可见佣金流水
- 所有获得分润用户可见分润记录

**后台功能：**
- 订单收入统计
- 资金流水总览
- 分润明细查询

### 4.4 交付物
- 佣金结算服务
- 分润计算与发放服务
- 分润台账 API
- 前端：分润记录页面
- 后台：资金统计页面

### 4.5 测试要点
- [ ] 佣金正确计算并发放
- [ ] 三级分润正确分配
- [ ] 分润记录正确显示
- [ ] 后台可查看资金流水

## 注意事项

1. **代码隔离**：新增功能使用独立 Module，保持原有代码不动
2. **数据隔离**：服务订单与普通订单使用不同数据表
3. **权限控制**：服务人员功能需二次验证身份
4. **配置灵活**：所有开关支持随时切换
5. **日志完整**：关键操作记录日志便于排查
6. **用户扩展**：`service_provider` 表是扩展现有用户信息，不是新建用户
