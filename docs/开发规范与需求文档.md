
## 三、服务商分销模块需求

### 3.1 用户身份规则

1. **三类角色**：消费用户、平台管理员、服务人员
2. **申请流程**：普通用户可在手机端个人中心申请成为服务人员
3. **申请材料**：手机号、身份证正反面、工作证件、荣誉证书
4. **审核机制**：提交后由平台后台人工审核，审核通过才解锁服务人员全部权限

### 3.2 产品类型区分

1. **普通实物商品**：沿用系统原有下单、交易、结算流程，不作改动
2. **服务类产品**：走本次定制上门服务专属订单流程

### 3.3 服务产品完整业务流程

1. 平台后台发布服务类产品，发布时提前预设：服务人员佣金比例、三级推荐分润比例
2. 消费用户正常选购服务产品，下单并完成支付
3. 订单同步至平台后台，后台支持修改订单地址等信息
4. 订单审核：后台配置开关，支持自动审核/人工审核两种模式，审核通过订单才进入抢单池
5. 仅已认证服务人员可查看抢单订单列表，根据自身条件自主抢单
6. 订单派单：后台配置开关，支持自动派单/人工派单；自动则抢单直接生效，人工可平台指派接单人员
7. 服务人员抵达现场后，上传现场合照凭证，点击开启服务
8. 服务完成后，服务人员手动提交结束订单
9. 订单收尾：用户可手动确认结束，未操作则按后台设定时长自动完结；完结后用户对订单做1-5星星级评价
10. 佣金结算：后台开关控制自动结算/平台审核后结算，按预设佣金自动划转费用给服务人员
11. 多级分润：后台单独分润操作按钮，支持手动执行分润；包含下单用户推荐链、服务人员推荐链三级分润

### 3.4 核心配置开关

1. **订单审核**：自动审核 / 人工审核
2. **订单派单**：自动确认接单 / 平台人工指派
3. **费用结算**：自动结算佣金 / 后台审核结算佣金
4. **各级三级分润**：单独开启、关闭权限
5. **订单自动完结时长自定义设置**

### 3.5 佣金计算规则

| 层级 | 佣金比例 | 说明 |
|------|---------|------|
| 一级推荐 | 10% | 直接推荐的用户购买 |
| 二级推荐 | 5% | 推荐的用户推荐的用户购买 |
| 三级推荐 | 2% | 间接推荐三层内 |

**服务商分润比例**：默认 70%（平台收取30%）

## 五、后续开发规范

> **重要**：后续所有新功能，统一套用项目里带底部导航栏的 React 移动端模板开发

### 5.1 移动端模板标准

所有移动端功能页面必须遵循以下标准：

1. **底部导航栏**：包含首页、个人中心这类栏目
2. **页面结构**：与现有模板保持一致
3. **样式规范**：跟随现有移动端模板的设计标准

### 5.2 模板参考位置

```
medushaV2-storefront/src/modules/
├── ygn/                    # 忆光年核心功能（参考模板）
│   ├── home/              # 首页
│   ├── memories/          # 我的回忆
│   ├── configure/         # 配置页面
│   ├── generate/          # 生成页面
│   └── person-manager/    # 人员管理
```

### 5.3 组件命名规范

- **文件**：kebab-case.tsx 或 kebab-case.ts
- **组件**：PascalCase（如 ProductCard）
- **函数/变量**：camelCase（如 retrieveCart）
- **Server Actions**：前缀动词（如 addToCart）
- **常量**：SCREAMING_SNAKE_CASE

### 5.4 导入顺序

1. React/Next.js 核心导入
2. 外部库
3. 内部导入使用路径别名（@lib/*, @modules/*）
4. 类型导入
5. 相对导入（./, ../）

### 5.5 技术规范

- **Next.js 15 App Router**：默认使用 Server Components
- **React 19**：Async Server Components 为标准
- **Medusa v2 SDK**：使用 @medusajs/js-sdk
- **缓存管理**：mutation 后使用 revalidateTag()
- **TypeScript**：严格模式启用

### 5.6 新功能开发流程

1. 在 `src/modules/` 下创建功能模块
2. 按上述模板标准开发页面和组件
3. 添加对应的 API 路由（后端）
4. 编写测试用例
5. 更新本文档
