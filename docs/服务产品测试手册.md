# 服务产品功能测试手册

## 测试前准备

### 1. 环境启动
```bash
# 启动后端服务
cd medushaV2
npm run dev

# 启动前端服务
cd medushaV2-storefront
yarn dev
```

### 2. 运行数据库迁移
```bash
cd medushaV2
npx ts-node src/scripts/migrate-service-fields.ts
```

### 3. 获取 API Key
在 Medusa Admin 后台获取 Publishable API Key

---

## 核心功能测试

### T1: 服务产品浏览

**API 测试**
```bash
curl -X GET "http://localhost:9000/store/service-products" \
  -H "x-publishable-api-key: YOUR_API_KEY"
```

**前端测试**
1. 访问 http://localhost:8000/service
2. 确认显示服务产品列表
3. 确认 Tab 切换正常

---

### T2: 购买服务产品

**流程**
1. 用户登录
2. 选择服务产品
3. 点击购买
4. 填写服务需求
5. 提交订单

**预期结果**
- 创建 service_order 记录
- 订单状态为 "pending"

---

### T3: 服务商申请

**流程**
1. 访问 /account/service-provider
2. 填写申请表单
3. 提交申请

**预期结果**
- 创建 service_provider_application 记录
- 状态为 "pending"

**Admin 审核**
1. 访问 Admin 后台
2. 找到服务管理 Widget（或直接调用 API）
3. 审批申请

```bash
# 审批 API
curl -X POST "http://localhost:9000/admin/service-applications/{id}" \
  -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action": "approve"}'
```

---

### T4: 服务商接单（抢单）

**流程**
1. 服务商登录
2. 访问 /service
3. 切换到 "服务商订单" Tab
4. 点击 "抢单" 按钮

**API 测试**
```bash
curl -X POST "http://localhost:9000/store/service-orders/{orderId}" \
  -H "Authorization: Bearer USER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action": "accept"}'
```

**预期结果**
- 订单状态变为 "accepted"
- provider_id 填充为当前用户 ID

---

### T5: 上传服务结果

**流程**
1. 服务商点击已接订单
2. 点击 "上传服务结果"
3. 选择文件上传
4. 确认完成

**API 测试**
```bash
curl -X POST "http://localhost:9000/store/service-orders/{orderId}" \
  -H "Authorization: Bearer USER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "complete",
    "result_url": "https://example.com/result.jpg"
  }'
```

**预期结果**
- 订单状态变为 "completed"
- result_url 填充

---

### T6: 客户评价

**流程**
1. 客户登录
2. 访问 /service
3. 切换到 "我的订单" Tab
4. 点击已完成订单
5. 点击 "评价服务"
6. 选择评分并填写评价
7. 提交

**API 测试**
```bash
curl -X POST "http://localhost:9000/store/service-orders/{orderId}" \
  -H "Authorization: Bearer USER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "review",
    "rating": 5,
    "comment": "服务很好！"
  }'
```

**预期结果**
- rating, review_comment, reviewed_at 字段填充

---

### T7: 查看团队

**流程**
1. 用户登录
2. 访问 /account/team

**API 测试**
```bash
curl -X GET "http://localhost:9000/store/team" \
  -H "Authorization: Bearer USER_TOKEN"
```

**预期结果**
- 返回团队成员列表
- 按层级分组（level1, level2, level3）

---

### T8: 抢单/派单模式切换

**Admin 设置**
```bash
# 查看当前模式
curl -X GET "http://localhost:9000/admin/order-mode" \
  -H "Authorization: Bearer ADMIN_TOKEN"

# 切换模式
curl -X POST "http://localhost:9000/admin/order-mode" \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode": "grab"}'  # 或 "assigned"
```

**前端测试**
1. 访问 /account/order-mode
2. 查看当前模式
3. 切换模式
4. 确认更新成功

## 问题排查

### API 返回 401 Unauthorized
- 检查 Authorization Header 是否正确
- 确认用户已登录

### API 返回 403 Forbidden
- 检查用户权限
- 确认操作授权

### 数据库字段未找到
- 运行迁移脚本
- 检查数据库连接

### 前端组件报错
- 检查 import 路径
- 确认组件属性正确传递
